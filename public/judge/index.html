Allowance, in 30 seconds

Allowance gives every outside contributor a capped Otari allowance; on /repro an open-weight model writes a test, Otari's sandbox runs it, and the verdict is what the run did, not what the model believes.

The 30-second path

  1. Open issue #6: a screenshot bug report. The bot's comment says Reproduced, return code 1, and shows the exact script it ran and the sandbox output.
  2. Open issue #4: a report of a bug that is not there. Not reproduced, return code 0. The footer counts the MCP tool calls (mcp ×5).
  3. Open issue #7: the model's repair turn changed the expected value, and Allowance refused to run it. The model cannot argue its way to a verdict.
  4. Open issue #5: a prompt-injection issue, blocked by the guardrail with 403 guardrail_violation before any coder model saw it.
  5. Open issue #1: the footer reads $0.05 of $0.05 left today, read back from the Otari end-user record; after the runs it reads $0.0000 of $0.05.
  6. Want to try it? Open an issue on allowance-demo and comment /repro. You run on your own $0.05/day allowance.

Receipts

  • Open-weight models only, all through the hosted Otari gateway.
  • 166 tests in CI at 100% line, branch and function coverage, including a property test: across 25,000 generated sandbox runs, a Reproduced verdict only ever came from a failed run with the marker's AssertionError in stderr.
  • Every verdict comment prints its Otari request id, the model cost and the sandbox run count.

Reproduce it

git clone -b otari https://github.com/edycutjong/allowance && cd allowance
npm ci && npm test
# dry run against a real issue, no GitHub writes (needs Otari keys):
node --experimental-strip-types scripts/repro.ts https://github.com/edycutjong/allowance-demo/issues/4 --as you

There is no mock mode: the dry run calls Otari and the sandbox for real.

Honest limits

  • The demo bugs are in a repository we planted; issues #1–#7 are the development transcript, early failed runs kept.
  • The routing fallback to Qwen3-VL has not fired on the GitHub path; the first target accepted the screenshot.
  • Otari guardrails screen the request text, not MCP/web-fetch results inside Otari's tool loop.
